Hi all,
I'm wondering if anyone could help me with the following question:

Scheme of the 2-bit mapping for I2_S quantization looks like following: -1:00, 0:01, 1:10 (according to the paper and quantization function).
Function ggml_vec_dot_i2_i8_s implemented in the way that it doesn't even use this mapping and that is so interesting! It just treats quantized data as non-mapped (e.g. 0:00, 1: 01, 2: 10, etc). In the test.cc there is a correction for that being made after the function (effectively, postprocessing addresses that, so function works correctly).

My understanding is that the same happens during inference and that's probably an architectural limitation for that in the llama.cpp. Most likely as that might be a standard practice for the quantization (historically?). 

So, I'm really wondering about following things:
1) Why this type of postprocessing is used? Is for that historic and architectural reasons? 
2) Where this postprocessing is being done during inference? (specifically, which part of the source code is responsible for that - I'm new to the model inference and llama.cpp, and I was not able to figure that out). Is there any documentation on that? Where should I look?
