A byte is able to store 5 trits, but you need to encode them in a more complex manner.

Have you considered doing this to save almost 20% memory at the cost of some bitwise operations per lookup?

Possible techniques:
- just add them together, multiplying each time by 3
- 5 243-byte lookup tables, one for each trit
- use smaller lookup tables and some arithmetic
