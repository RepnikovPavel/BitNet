## Description

Found three error handling bugs while reviewing the codebase.

### 1. `e2e_benchmark.py:23` — `sys.exit(1)` always executes (actively triggered)

```python
# utils/e2e_benchmark.py:18-23
else:
    try:
        subprocess.run(command, shell=shell, check=True)
    except subprocess.CalledProcessError as e:
        logging.error(f"Error occurred while running command: {e}")
    sys.exit(1)  # outside except block — runs on success too
```

`sys.exit(1)` is at the `else` block level, not inside `except`. Since line 46 calls `run_command(command)` without `log_step`, the `else` branch is taken and the benchmark always exits with error code 1, even on success.

### 2. `setup_env.py:107` — same indentation issue (currently latent)

Same pattern as above. Not actively triggered because all current call sites pass `log_step`, but would break if `run_command()` is ever called without it.

### 3. `setup_env.py:212` — `exit(0)` on error condition

```python
if arch not in COMPILER_EXTRA_ARGS.keys():
    logging.error(f"Arch {arch} is not supported yet")
    exit(0)  # error condition but returns success code
```

Should be `sys.exit(1)`.

### Minor: `setup_env.py:85` — unhandled KeyError

```python
def system_info():
    return platform.system(), ARCH_ALIAS[platform.machine()]
```

On unrecognized platforms (e.g. `i686`, `riscv64`), this raises `KeyError` before the architecture check at line 210 can provide a proper error message.

## Expected behavior

- `sys.exit(1)` should only run on failure
- Error conditions should exit with non-zero code
- Unsupported architectures should get a clear error message
