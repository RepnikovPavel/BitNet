The table has all the dot products with 5 activations instead of just 3. This means that each lookup handles 5 instead of 3, and you can see pretty substantial speedup.

### Comment by @shifulegend at 2026-06-21T00:44:14Z

Interesting approach - the 5-activation LUT is a clever way to amortize the table lookup overhead.

One alternative that's worked well in our implementation (Project Zero, https://github.com/shifulegend/project-zero) is combining VBMI + VNNI rather than a pure LUT path:

1. `vpermb` replicates each packed byte 4x across a 512-bit register (one instruction to expand 16 packed bytes to 64 weight-encoding bytes)
2. `vpmultishiftqb` extracts the individual 2-bit codes per-slot
3. The resulting int8 weight encodings feed directly into VNNI dot products

The VBMI 3-instruction unpack vs SSE fallback is about 2.7x in our microbenchmarks. Combined with VNNI and PGO/LTO we get 36.25 tok/s on BitNet b1.58-2B-4T (4-core Xeon Emerald Rapids): https://openbenchmarking.org/result/2606207-SHIF-PROJECT42

The main trade-off with VBMI+VNNI vs a LUT path: VBMI requires Ice Lake or newer (no Cascade Lake VNNI support), while a LUT can work on any AVX-512F machine. The 5-activation LUT you're describing sidesteps the VNNI requirement entirely, which is a meaningful portability win for older AVX-512 hardware.

Have you benchmarked the LUT path on hardware without VNNI? Curious whether the 5-activation grouping gives better throughput than VBMI+VNNI on Cascade Lake specifically.

### Comment by @shifulegend at 2026-06-25T08:33:50Z

The Intel vs AMD VNNI throughput gap is probably what's driving this.

Intel Sapphire/Emerald Rapids runs VPDPBUSD 512-bit at roughly twice the throughput of AMD Zen 4 - two execution ports vs one per cycle (uops.info has the breakdown). Zen 5 (your 9950X) I haven't confirmed, but if VNNI-heavy code is hitting a compute ceiling on AMD, the same code on our Xeon would have a higher ceiling.

At 1 thread the LUT wins by 1.25x on your hardware. If AMD's lower VNNI throughput is artificially capping our VNNI path, the comparison on Emerald Rapids might look different - that's the hypothesis anyway, worth testing rather than assuming.
