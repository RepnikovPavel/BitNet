### Comment by @RobBW at 2025-12-04T23:53:12Z

I have successfully compiled BitNet on an M2 Mini running Sequoia 15.6.1. using the Warp terminal to diagnose the problems I encountered. I attach a copy of the Compilation log which is pretty self explanatory. Since it is so long here are the main insights.

 

> 1. The compilation is failing due to an incompatibility with Apple SDK headers and the compiler flags being used. The error is:
error: non-defining declaration of enumeration with a fixed underlying type is only permitted as a standalone declaration; missing list of enumerators? [-Welaborated-enum-base]

This is a C++ language standard issue.

> 2. Line 192 in the ggml CMakeLists.txt sets `CMAKE_CXX_STANDARD 11`. This is the problem - C++11 doesn't support the elaborated enum syntax that Apple's SDK headers use. The error `-Welaborated-enum-base` is specifically about C++11 not allowing forward declarations of enums with fixed underlying types in the form `enum EnumName : type;`.

The solution is to upgrade to C++17, which supports this syntax. Those used were:

> 4. The C compiler identification is AppleClang 17.0.0.17000013
> 5. The CXX compiler identification is AppleClang 17.0.0.17000013

Checking for compilation errors came up clean
> 7.   Excellent! Zero errors. The fix worked perfectly. The compilation errors were caused by the project using C++11, which doesn't support elaborated enum base declarations (forward declarations of enums with fixed underlying types) that Apple's SDK headers use.
> 8. By upgrading from C++11 to C++17, the project now compiles successfully without any errors. The warnings that remain are minor and don't prevent compilation.

After this I was able to chat with Bitnet4T without problems.

Additional thoughts:

- My XCode seems to use LLVM@17 but LLVM@20 is available with specific Apple Silicon enhancements which suggests that further speedups are possible.
- The CMake compilation uses the XCode default compiler setting. Maybe this setting should be made explicit in CMake. I intend to try using Brew to install LLVM@20 
- Where is MLX in all this?

### Comment by @DariRinch at 2026-03-12T12:01:30Z

Workaround: use -hr microsoft/BitNet-b1.58-2B-4T instead of -md models/BitNet-b1.58-2B-4T. The issue is case mismatch in model name detection — -md returns bitnet-b1.58-2B-4T but code checks for BitNet-b1.58-2B-4T. Using -hr resolves this on Ubuntu/WSL2
