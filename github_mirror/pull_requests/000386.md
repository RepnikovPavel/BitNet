# PR #386: [Core] Thread-safe code generation for BitNet kernels

- state: open

- updated_at: 2026-01-29T18:19:18Z

---

Identified a potential race condition in the generated 'bitnet-lut-kernels.h' when multiple inference requests are processed concurrently (e.g., in 'llama-server').

The Issue: The global 'bitnet_tensor_extras_index' was a static size_t, leading to data races during 'ggml_bitnet_transform_tensor' calls from multiple threads.
The Fix:
- Patched 'utils/codegen_tl1.py' and 'utils/codegen_tl2.py' to use 'std::atomic<size_t>' for the index.
- Implemented atomicity using 'fetch_add(1)' to safely allocate indices.
- Added necessary headers (<atomic>, <cstdio>) to the generated output.
Impact: Makes BitNet kernels thread-safe and suitable for multi-user server environments.
