  - Fix multiple compilation errors that prevent TL2 kernel builds on Windows with Clang targeting MSVC
  - Add pre-generated TL2 LUT kernels for Qwen2.5-32B (32.77B params, 2.74 BPW)
  - Add Qwen2.5-32B matrix dimensions to codegen_tl2.py

  Problem

  The TL2 x86 kernel path does not compile on Windows (Clang 18+ with MSVC toolchain) due to:

  1. C++17 not enabled — ggml/CMakeLists.txt only sets C++17 for SYCL builds, but TL2 targets also need it (uses <chrono> transitively)
  2. Missing #include <chrono> — common.cpp, log.cpp, imatrix.cpp, perplexity.cpp use std::chrono without including the header (works on GCC/Linux due to transitive includes, fails on Clang/MSVC)
  3. Implicit pointer casts — ggml.c TL2 path assigns char* to bitnet_float_type* and passes float* where ggml_fp16_t* is expected (C allows implicit void* conversion but Clang warns/errors on
  char* to typed pointer)
  4. Const correctness — ggml-bitnet-mad.cpp assigns const int8_t* to int8_t*

  Changes

  Main repo:
  - CMakeLists.txt — set CMAKE_CXX_STANDARD 17 at project root
  - src/ggml-bitnet-mad.cpp — add const qualifier to fix -Werror
  - utils/codegen_tl2.py — add Qwen2.5-32B-TL2 model entry (dims: 5120x5120, 1024x5120, 27648x5120, 5120x27648)
  - include/bitnet-lut-kernels.h — pre-generated TL2 LUT kernels for Qwen2.5-32B
  - include/kernel_config.ini — kernel block config (BM=256/128, BK=96, bm=32)

  Submodule patch (windows-tl2-build-fixes.patch, apply to 3rdparty/llama.cpp):
  - ggml/CMakeLists.txt — enable C++17 when GGML_BITNET_X86_TL2 is ON
  - ggml/src/ggml.c — add explicit pointer casts in both TL1 and TL2 mul_mat paths
  - common/common.cpp, common/log.cpp, examples/imatrix/imatrix.cpp, examples/perplexity/perplexity.cpp — add #include <chrono>

  Test plan

  - Builds with Clang 22.1.2 + MSVC BuildTools + Ninja on Windows 11
  - Inference verified on Qwen2.5-32B TL2 GGUF (correct output: "The sum of 2 and 2 is 4")
  - Benchmarked on Intel 12700K (8P+4E, AVX2): 2.6 tok/s generation, 4.55 tok/s prompt eval at 16 threads
  - Verify no regression on Linux x86_64 builds
  - Verify no regression on ARM TL1 builds
