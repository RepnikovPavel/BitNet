## Summary

On Windows with ClangCL toolset (as reported in issue #493), the `setup_env.py` script passes `-DCMAKE_C_COMPILER=clang` and `-DCMAKE_CXX_COMPILER=clang++` flags which conflict with the `-T ClangCL` flag. This causes CMake configuration to fail with "The C compiler identification is unknown".

## Problem

In `setup_env.py`, line 214 unconditionally passes compiler flags:
```python
run_command(["cmake", "-B", "build", ..., "-DCMAKE_C_COMPILER=clang", "-DCMAKE_CXX_COMPILER=clang++"])
```

When building on Windows with `-T ClangCL`, explicitly setting the compiler path confuses CMake and MSBuild.

## Solution

Conditionally pass the compiler flags only on non-Windows platforms:

```python
if platform.system() == "Windows":
    run_command(["cmake", "-B", "build", ...])  # No explicit compiler flags
else:
    run_command(["cmake", "-B", "build", ..., "-DCMAKE_C_COMPILER=clang", "-DCMAKE_CXX_COMPILER=clang++"])
```

This matches the suggested fix in issue #493.

## Testing

This fix resolves the Windows CMake configuration error. The change is safe as it only affects Windows builds - other platforms continue to work as before.
